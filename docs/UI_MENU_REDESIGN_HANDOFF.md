# Верхнее меню и нижняя панель: handoff для следующей итерации

Статус: проект находится на чистом `master` после релиза `v0.4.0`.
Этот документ описывает следующую визуальную итерацию. Код в рамках подготовки
handoff не изменялся.

Особенно важны три свойства MC:

2. Активная категория получает заметный тёмный фон; выпадающее меню визуально

3. Нижняя строка состоит из самостоятельных действий, но клавиша и название

## Проблема `v0.4.0`

- Символы `│` между верхними категориями создают лишний визуальный шум.
- Верхнее меню и нижняя панель выглядят как два варианта одного компонента,
  хотя имеют разные роли: навигация против контекстных действий.
- Одинаковые буквы принадлежат разным действиям. Например, `P` визуально
  обозначает верхнюю категорию Peer, но plain `P` запускает нижнее действие
  Password.
- Нижняя панель печатает клавишу отдельным префиксом (`P Password`), хотя
  достаточно подсветить букву непосредственно в слове (`Password`).
- Подсветка обещает пользователю shortcut, но модификатор верхнего меню не
  объяснён визуально и в help.

Это не набор отдельных косметических дефектов. Нужны две явные области
accelerators с разными правилами.

## Согласованная модель клавиш

### Верхнее меню — навигационная область

- Категории: Server, Peer, View, Tools, Help.
- Мышь: клик по категории открывает её dropdown.
- Клавиатура: `Alt+подсвеченная буква` открывает категорию:
  `Alt+S`, `Alt+P`, `Alt+V`, `Alt+T`, `Alt+H`.
- Plain-буква верхней категории никогда не перехватывает контекстное действие.
- Когда dropdown открыт, Left/Right меняют категорию, Up/Down выбирают строку,
  Enter запускает, Esc закрывает.
- `M` может остаться универсальным plain-shortcut для открытия/закрытия меню.

Таким образом, `Alt+P` всегда означает Peer menu, а plain `P` на списке
серверов — Password. Конфликта обещаний больше нет.

### Нижняя панель — область контекстных действий

- Используются plain-буквы без `Alt`.
- Буква подсвечивается **внутри названия**, а не выводится отдельной колонкой:
  `Help`, `New`, `Open`, `Edit`, `Remove`, `Password`, `Menu`, `Quit`.
- Для действия хранится явная пара `label + accelerator`. Рендерер находит
  соответствующий символ внутри label и применяет к нему стиль.
- Accelerator не обязан быть первой буквой. Если в одной панели появляются
  конфликты, разрешено выбрать другой естественный символ внутри слова.
- Все accelerators текущей панели должны быть уникальны без учёта регистра.
- Клик по всему сегменту выполняет то же действие, что и подсвеченная буква.
- Disabled-сегмент остаётся видимым, приглушённым и не реагирует ни на мышь,
  ни на клавиатуру.

Скрытые F-key aliases можно сохранить только для обратной совместимости. Они
не показываются в основном интерфейсе и не участвуют в визуальной модели.

## Визуальный контракт верхнего меню

- Удалить все текстовые разделители `│` и не заменять их рамками.
- Между категориями оставить только равномерный горизонтальный padding.
- Неактивная строка: единый спокойный cyan/teal фон, тёмный читаемый текст.
- Подсвеченная буква заметна, но не делает всю строку пёстрой.
- Hover не требуется; терминалы реализуют его непредсказуемо.
- Активная категория: тёмный/чёрный фон и контрастный текст, как у MC.
- Открытый dropdown начинается непосредственно под активной категорией.
- Выбранная строка dropdown использует тот же активный тёмный фон.
- Закрытие dropdown возвращает верхнюю строку в спокойное состояние; не нужно
  постоянно выделять Server/Peer/View только потому, что открыт связанный экран.

Последний пункт важен: selected navigation state и open menu state — разные
состояния. В референсе MC верхнее меню спокойно, пока пользователь с ним не
взаимодействует.

## Визуальный контракт нижней панели

- Сохранить удачные высококонтрастные прямоугольные сегменты `v0.4.0`.
- Убрать отдельную тёмную ячейку/префикс с буквой.
- Рисовать одну цельную подпись на одном фоне; только символ accelerator имеет
  отдельный foreground/bold/underline style.
- Сегменты остаются одинаково аккуратными по высоте и полностью заполняют
  последнюю строку терминала.
- Допустим небольшой тёмный промежуток между сегментами, как у MC; символ `│`
  не использовать.
- Названия сокращаются только после сохранения видимой accelerator-буквы.
- Нижняя строка остаётся физически закреплена к последней строке терминала;
  mouse hit-area обязан совпадать с отрисованным сегментом после resize/status.

## Рекомендуемые действия по экранам

### Server list

`Help`, `New`, `Open`, `Edit`, `Remove`, `Password`, `Menu`, `Quit`.

### Server overview

`Help`, `Refresh`, `Install` (только если WireGuard отсутствует), `Configure`
(только если WireGuard установлен), `Diagnose`, `Back`, `Menu`, `Quit`.

### Peers

`Help`, `New`, `Actions`, `Revoke`, `Refresh`, `Diagnose`, `Back`, `Menu`,
`Quit`. Недоступные действия видимы, но приглушены.

Не следует пытаться сохранить одинаковое количество сегментов на всех экранах.
Стабильны значения действий и их буквы; состав панели контекстный.

## Требования к реализации

1. Переименовать внутренние сущности так, чтобы код различал `menu category
   accelerator` и `context action accelerator`.
2. Не вычислять accelerator категории из первой буквы label неявно; хранить его
   явно рядом с категорией.
3. Создать единый renderer `renderAcceleratedLabel(label, key, styles...)`,
   ANSI-safe и Unicode-safe.
4. Mouse hit testing должен использовать ту же вычисленную геометрию сегментов,
   что и renderer, а не повторять формулу отдельно.
5. Keyboard dispatch сначала обрабатывает modal/menu state, затем `Alt+category`,
   затем контекстные plain actions. Disabled action не должна проваливаться в
   старый screen handler.
6. Help обязан явно говорить: `Alt+letter — top menu`, `letter — bottom action`.
7. Документы `README.md`, `docs/TUI.md` и `docs/COMMANDER_UI.md` обновляются после
   утверждения реализации.

## Обязательные тесты приёмки

- Верхняя строка не содержит `│` ни при одной поддерживаемой ширине.
- В закрытом состоянии ни одна категория не имеет active background.
- Открытая категория и выбранная dropdown-строка имеют active background.
- `Alt+P` открывает Peer; plain `P` на server list открывает Password.
- Все plain accelerators каждой нижней панели уникальны.
- Нижняя строка не содержит шаблонов вида `P Password` или отдельных key cells.
- Подсвеченная буква действительно находится внутри отображаемого label.
- Click и клавиша dispatch-ят один и тот же action.
- Disabled click и disabled shortcut ничего не выполняют.
- Геометрия и hit-area совпадают на `64×18`, `90×24`, `135×24`, `166×34`,
  после уменьшения окна и при видимом status banner.
- Рендер каждой строки не превышает ширину терминала; весь view не превышает
  высоту терминала.
- Race, responsive property tests, Darwin amd64/arm64 builds и GoReleaser
  snapshot остаются зелёными.

## Что не менять в этой итерации

- Go/Bubble Tea/lipgloss и `CGO_ENABLED=0` остаются архитектурным выбором.
- Бизнес-логику WireGuard, SSH, sudo, vault и peer lifecycle не переписывать.
- Не возвращать парольные prompts в обычный терминал.
- Не менять минимальный размер `64×18`, пока новая геометрия не докажет другую
  необходимость тестами.

## Definition of done

Пользователь без чтения документации видит две разные системы:

- спокойное верхнее меню, открываемое мышью или `Alt+подсвеченная буква`;
- контекстные действия внизу, запускаемые plain подсвеченной буквой.

Ни одна подсветка не обещает действие, которое выполняется другой клавишей.
Интерфейс остаётся корректным при resize, мышь и клавиатура всегда вызывают
один action, а весь release test matrix проходит без регрессий.
